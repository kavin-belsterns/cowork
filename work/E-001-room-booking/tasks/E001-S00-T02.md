## Dispatch note
- Test DB: throwaway container `e001-testdb` (postgres 18.7) at `127.0.0.1:5434`, database `e001_test`, superuser `app_owner`. The full URL is in the shell variable `TEST_DATABASE_URL`, set by the lead. Never write the password into a tracked file.
- pnpm needs the sandbox off (T-01 evidence note 3).
- Migration name: `<timestamp>_e001_init`. Generate the table part with `prisma migrate dev --create-only`, then append raw SQL in the same `migration.sql`: `CREATE EXTENSION IF NOT EXISTS btree_gist`, the exclusion constraint from ADR-0006 exactly, the partial uniques, `lower(email)` unique, every CHECK in spec section 4 and T-01 evidence note 8 (including `weekday BETWEEN 1 AND 7`), the audit row trigger (UPDATE, DELETE) and statement trigger (TRUNCATE) that raise.
- Roles: create `app_web` and `app_worker` idempotently (NOLOGIN in the migration; passwords and LOGIN are set by ops and CI, never in SQL). Grants exactly as spec section 4. `REVOKE TRUNCATE` from both. CI expects these names (T-01 evidence note 9).
- `src/lib/db.ts`: the only `new PrismaClient(`. Prisma 7 driver adapter for Postgres. Reads the URL through `src/lib/env.ts` (`DATABASE_URL_WEB` for web, `DATABASE_URL_WORKER` when a role argument says worker). Exports the client and a `withRetry` helper that re-runs a whole interactive transaction on P2034 or 40001, at most 3 times. Starts with `import 'server-only'`.
- `src/lib/audit.ts`: `writeAudit(tx, event)` inserts one `audit_events` row inside the caller's transaction. Event shape from `src/contracts/history.ts`. Rejects any `details` key that the logger would redact (no personal data).
- `prisma/seed.ts`: idempotent. Data exactly as spec section 4 test seed: 2 offices (`Asia/Kolkata`, `Europe/London`), hours Mon to Fri 08:00 to 20:00, 4 rooms each, one user per role per office plus one platform admin, one user with `must_change_password = true`, one deactivated user, today's bookings and visits, visits older than 90 days. Known test password for seed users comes from env `SEED_PASSWORD` with a test default only when `NODE_ENV` is not production. Print a one-line summary.
- No unit tests in this task: the db, audit and migration tests are T-05's (`tests/unit/lib/**`, `tests/integration/contracts/**`).
