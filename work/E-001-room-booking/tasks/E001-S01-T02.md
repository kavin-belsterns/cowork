## Dispatch note
- Both files start with `import 'server-only'` and use `getDb('web')`. Inputs are hashes, never raw tokens or emails: hashing lives in `src/lib/auth` (T-03).
- `session.ts`: `findSessionByTokenHash(hash, now)` returns the row with the fields `SessionUser` needs, or null. An expired row is deleted and returns null. A deactivated user returns null. `deleteSession(hash)`.
- `verifyCredentials(email, verify)`: load by `lower(email)`. `verify(hash | null)` is a callback T-03 supplies (Argon2id or dummy verify on null). Return `{ ok: false }` or `{ ok: true, user: { id, deactivated, tempPasswordExpiresAt, mustChangePassword } }`. Never return the hash.
- `createSessionAfterSignIn({ userId, emailHash, tokenHash, expiresAt })`: one transaction inserts the session and deletes that email hash's attempts.
- `checkOwnPassword(userId, verify)`: boolean, hash stays inside.
- `setOwnPassword({ userId, version, newHash, tokenHash, expiresAt })`: one interactive transaction. `updateMany where id and version` sets the hash, `must_change_password` false, `temp_password_expires_at` null, `version` + 1. 0 rows throws `VersionConflictError`. Delete all the user's sessions, insert the new one, `writeAudit` a password change event. Retry the whole tx on P2034 or 40001 as `src/lib/db.ts` does, at most 3 times.
- `sign-in-attempt.ts`: `recordFailure(emailHash, ip, at)`, `countFailures(emailHash, since)`, `countDistinctEmailsByIp(ip, since)`. Use indexes `sign_in_attempts_email_at_idx` and `sign_in_attempts_ip_at_idx`.
- Tests run against the live test DB as role `app_web` (the URL sets `role=app_web`). Set up fixture rows with a separate `pg` client on `DATABASE_URL_MIGRATOR`. Use unique emails and ids per run. Delete what you create. Never edit seed users.
- When the DB is unreachable the tests must FAIL, never skip or pass.
